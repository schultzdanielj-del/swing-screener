**Last updated:** 2026-03-27

## Architecture

**Local (desktop):**
- Native PySide6 desktop app (`scanperfect.py`) — no browser, no server process
- SQLite DB (`data/scanperfect.db`): examples, setups, vetting decisions, earnings, pending reviews, rejected signals
- daily OHLCV pickle loaded into memory at startup (~4,169 tickers in 0.5s) — all chart data instant
- All caches: expression cache, market cache, fundamentals — local files
- Grind results: local JSON files in `local_runner/cache/` and `data/`
- Pipeline runs as subprocesses launched from PySide6 app via QProcess with auto-chaining
- Start with: `python scanperfect.py` or double-click `ScanPerfect.bat`

**Railway (seed vault only):**
- File mirror API: receives daily backups + grind result JSONs
- No UI, no server logic, no pipeline coordination
- Claude reads grind results from here during chat sessions
- Endpoint: `POST /api/v2/files` (file mirror)

## Seed Vault (Daily Backup)

Step 8 of nightly refresh (4:30pm ET). Runs every night regardless of whether there's new market data.

Backs up only non-rebuildable data to Railway file mirror (JSON files only — no Railway DB sync). Non-rebuildable means human decisions and expensive compute results. Does NOT back up tables or files that can be cheaply regenerated by nightly pipeline or build scripts.

**SQLite tables backed up (13):**
1. `examples` — manual example trades
2. `setups` — setup type definitions
3. `pending_examples` — examples awaiting review
4. `rejected_signals` — vetting rejections
5. `grind_cycles` — beam search cycle metadata
6. `cycle_conditions` — signal grind conditions (hours of compute)
7. `cycle_signals` — signals found by grinders
8. `cycle_sacrificial_signals` — sacrificial signals from refinement
9. `exit_conditions` — exit grind results
10. `cycle_health` — cycle health metrics
11. `regime_model` — EV grinder regime model
12. `signal_regime_scores` — EV grinder signal scores
13. `nightly_watchlist` — watchlist output

**SQLite tables NOT backed up (rebuildable):**
- `earnings_dates` — refetched nightly from Yahoo Finance
- `ohlcv` — rebuilt by cache_builder
- `universe_ohlcv` — rebuilt by cache_builder
- `tradable_universe` — rebuilt by nightly pipeline
- `file_mirror` — Railway sync state
- `task_queue`, `research_jobs` — transient

**JSON file patterns backed up:**
1. `data/signal_filter/filtered_*.json` — signal filter outputs
2. `data/signal_exit_grind/signal_exit_*.json` — exit grind outputs
3. `data/exit_grind/exit_grind_*.json` — exit grind outputs
4. `data/profit_grind/profit_*.json` — profit grinder outputs
5. `data/pyramid_results_*.json` — pyramid/signal grind outputs
6. `local_runner/cache/ev_*.json` — EV grinder outputs
7. `local_runner/cache/refinement_*.json` — refinement grinder outputs
8. `local_runner/cache/raw_signal_clusters_*.json` — raw signal cluster data

**NOT backed up (rebuildable or legacy):**
- Expression cache (~21 GB), market cache, fundamentals cache — regenerated by build scripts
- `dtss_expressions.json`, `dtss_lsp_data.json` — legacy/orphaned files
- Brute expressions — deterministically generated by `brute_expressions.py`

**Known legacy issue:** Several active scripts still read examples from Railway's DB API (`/api/examples/`) instead of local SQLite. These include `matrix_builder.py`, `exit_grinder.py`, `cycle_health.py`, `signal_filter.py`, `signal_exit_grinder.py`. Future cleanup task — switch all to local SQLite.

Recovery (new machine):
1. Clone repo from GitHub
2. `pip install -r requirements.txt`
3. `python scripts/seed_vault.py --restore`
4. `python local_runner/cache_builder.py --daily --force` (~30 min)
5. `python local_runner/expr_cache_builder.py --build` (~2 hrs)
6. `python local_runner/nightly.py --force` (~20 min)
7. `python scanperfect.py` — done
